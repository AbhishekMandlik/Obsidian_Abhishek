## Python Interpreter
An interpreter is a programs that reads your python code, translates it into machine-understandable instructions (indirectly), and executes it.

Unlike C++, Python is not compiled directly into machine code of time. 

```
Python Code(.py)
	  |
Interpreter
	  |
Bytecode (.pyc)
	  |
Python Virtual Machine (PVM)
	  |
Machine Instructions		
```

### What actually happens?
#### Step 1: Lexical Analysis
The interpreter converts the text into tokens:
```
NAME x 
= 
NUMBER 5.
```
#### Step 2: Parsing
It checks whether the syntax is valid.
**Abstract Syntax Tree (AST)**

```
Assignemnt
	|
  x = 5
```
If syntax is wrong it will throw SyntaxError because the parsing fails.

#### Step 3: Compilation to Bytecode
The AST is converted to Python bytecode.
Bytecode is platform-independent.

```
Example instructions look like:
LOAD_CONST
STORE_NAME
LOAD_NAME
BINARY_ADD
PRINT_EXPR
```

#### Step 4: Execution by the Python Virtual Machine (PVM)
```
LOAD_CONST
↓
push value onto stack
↓
BINARY_ADD
↓
perform addition
↓
PRINT
↓
display output.
```

Why compile to bytecode?
The bytecoe can be cached, that is why we can often see something like __pycache__/ containing
%% module.cpython-313.pyc%%

These .pyc files let Python skip recompiling unchanged modules, Improving startup performance.

## Python Garbage Collector
The **garbage collector (GC)** is responsible for reclaiming memory occupied by objects that are no longer needed.
In CPython, memory management has two complementary mechanisms:
1. **Reference counting** (primary mechanism)
2. **Cyclic garbage collector** (handles reference cycles)


Reference counting
Every python object keeps track of how many references point to it.
If reference count becomes zero then the object is immediately de-allocated.

#### Reference counting:- Handled by Cyclic garbage collector.
Why is reference counting not enough?
Classic example of this would be:
a->Node A<-->Node B <- b
In a case like this if we remove external reference like a and b the two nodes still reference to each other. So each of them have a reference count of 1so space cant be reclaimed even if we are deleting the reference nodes.


### Cyclic Garbage collector:
The cyclic GC periodically searches for groups of objects that are only reachable from one another and not from anywhere else in the program. Then it frees the allocated memories.

#### When does the GC run?
It runs periodically based on allocation thresholds rather than after every statement.
```
#to interract with it manually.
import gc
gc.collect()

# to temporarily disable it.
gc.disable()
# this does not stop reference counting.
```

### Memory Allocation in Cpython
Python does not always return freed memory directly to the operating system. Cpython uses an internal allocator called as pymalloc for small objects, which keeps memory pools for reuse. As a result, a process's memory usage may not immediately decrease even after objects are freed.


# Interview Questions
### Q1. Why is Python slower than C++?
- Python is interpreted (compiled to byte-code and executed by the PVM at runtime).
- It is dynamically typed, so type checks occur at runtime.
- Objects have additional metadata and memory overhead.
- Each operation involves interpreter dispatch, unlike compiled native machine code.
---
### Q2. Does Python compile?
Yes. Python source code is compiled into **bytecode**, which is then executed by the Python Virtual Machine. It is not typically compiled directly into native machine code like C++.

---
### Q3. Why is a garbage collector needed if Python uses reference counting?
Reference counting cannot reclaim objects involved in **reference cycles**. The cyclic garbage collector detects and collects these unreachable cycles.

---
### Q4. What is the difference between bytecode and machine code?

| Bytecode                               | Machine Code                                        |
| -------------------------------------- | --------------------------------------------------- |
| Executed by the Python Virtual Machine | Executed directly by the CPU                        |
| Platform-independent                   | Platform-specific                                   |
| Generated by the Python compiler       | Generated by a native compiler such as GCC or Clang |
