### Why Network Security Matters
- External threats (DDoS, intrusion, IP spoofing).
- Internal risks(misconfiguration, lateral movement).
- Increasing cloud-native adoption = more exposure.
- Reliability and user trust.

### Firewalls and Reverse Proxies
- Firewall acts like a first line of defense  by deciding whether a network traffic should be allowed by filtering.
- Firewalls: filter traffic based on IP, port, protocol.
- Preventing unauthorised traffic from ever reaching your application.
- Types: Network-based, Host-based, Cloud firewalls.
- Reverse proxies: Every request first passes through proxies.  Route, Mask backend identity and add security.
- Examples: NGINX, AWS ALB

The proxy server(that sits between server inside a firewall and client) uses a regular mapping to forwards client requests to internal content servers. It appears to be the content server.

### Rate Limiting, Throttling, IP Filtering
1. Rate Limiting: per-user, per-IP request caps.(Prevent DDoS attacks, queues can also be used to do the same)
2. Throttling: graceful degradation under load. Application remains available for majority of the user rather than failing for all. (Or we can do is degradation of some services while keeping main functionality open -- different)
3. IP Filtering: Allow.block lists.
4. Helps protect APIs and backend systems from abuse.


### Network Segmentation and Isolation
Assume that the network breaches will happen and design the system so that this can not be done easily. This is the purpose of network segmentation.
1. Split the infra of network into zones: (public)DMZ, internal, DB etc.
2. Limit Lateral movement: Uf a web server is compromised they should not be able to compromise app server of Databases. As every hop between different layers would require passing through additional security controls -- making it very harder.
3. Use firewalls, subnets, private VLANs.
4. Cloud: use VPCs, security groups, NACLs.

### Zero Trust Security Model
- Never Trust, always verify.
- Auth every request, even inside a network.
- Micro-services: Mutual TLS, strict access control, operate with principle of least privilege.
- Applies to cloud, hybrid and on-prem setups.

### Securing Cloud Environments
- Shared Responsibility Model
- Key Aspects
	- IAM, excessive permissions, compromised credentials or poor access policies.
	- Encryption (EBS, S3, RDS)
	- Audit Logging (CloudTrail, Stackdriver)
- CSPM(Cloud Security Posture Management) tools: They scan your deployments and alert you before any security threat occurs.

### Securing Serverless and Containerised Workloads
- Serverless: Control IAM roles, execution timeouts from consuming resource indefinitely, API gateway access(Authentication, Authorisation, Rate limiting).
- Containers: Image Scanning, runtime hardening, least privilege. At runtime the containers should run as non-root user and have capabilities they require.
- Tools: AWS Lambda + API Gateway, Docker + Kubernetes security tools (OPA - policy enforcement, Falco- runtime threat detection)


### Security in Microservices
- Service to service auth (JWT, mTLS).
- API Gateway security: validation, auth, rate limits. It will sentalise common security concerns and keep individual services focused on business logic.
- Service mesh: fine-grained control, TLS, policies (lstio, Linkerd).

### Common Vulnerabilities (OWASP Top 10).
- A quick glance at top risks:
	- Injection: Untrusted input exploitation.
	- Broken Auth: Allows attackers to impersonate user.
	- Sensitive Data Exposure: Inadequate protection of confidential information.
	- Security Mis-config: Systems deployed insecurely.
	- XSS, CSRF, SSRF, etc.
- Relevance in web apps and micro-services.
- Focus on awareness + mitigation.
