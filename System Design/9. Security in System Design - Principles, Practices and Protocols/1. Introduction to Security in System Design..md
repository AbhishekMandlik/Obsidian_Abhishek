1. Security is non-functional requirement but critical for User Trust, Data Protection, System Reliability
2. Real-World examples: Data breaches (Equifax, Facebook etc.)

### Security in Distributed Systems
It has more entry points, more vulnerable.
Security Consideration:
1. Data in transit and at rest.
2. Authentication and Authorisation, every request should be treated as a security risk unless not verified.
3. Secure APIs and endpoint both internal and public facing. Their should be input validation, rate-limiting, secure communication and defences against common attacks.
4. Node and network-level protection.

### The CIA Triad:
Core of System Security: 
1. Confidentiality: Prevent un-authorised access. Also have different level of authentication through IAM and other things.
2. Integrity : Prevent data Tampering, Hashing, checksums and digital signatures help to prevent the data integrity.
3. Availability: Ensure system uptime and access. 

### Threat Modelling: Understanding your adversary
1. Define potential attackers and what they want.
2. Consider:
	1. Attack surface.
	2. Entry points.
	3. Assets to protect.
3. Tools: STRIDE model (Spoofing, Tampering, Repudiation, Info Disclosure, Denial of Service, Elevation of privilege). It is a structured checklist.
	1. Spoofing: Unauthorised person impersonates a legitimate user to gain access.
	2. Tampering: Unauthorised modification of data, while it rests on a drive or flows across a network.
	3. Repudiation: Attacker performs a malicious action and successfully denies doing it due to lack of evidence.
	4. Information Disclosure: Exposing private/ confidential information.
	5. Denial of Service: Exhaust system resources so legitimate users can't access the applications or service. (429 ERROR).
	6. Elevation of Privilege: Attacker exploits a flaw to gain higher admin access.

### Common Attack vectors
How attackers get in:
1. Insecure APIs: Unauthorised access, or no rate limit etc.
2. Misconfigured servers: storage left publicly accessible, default cred, excessive permissions or unpatched servers.
3. Poor Authentication: Strong password, multi-factor auth.
4. Open ports /services: Increase service.

### Common Attacks
1. DDoS: Distributed Denial of Service
	1. Flooding system with traffic to disrupt service.
	2. Target: Availability
	3. Mitigation:
		1. Rate Limiting
		2. Traffic scrubbing.
		3. Auto scaling and failover strategies.
2. Man-in-the-Middle(MITM) Attack:
	1. Attacker intercepts communication.
	2. Targets: Confidentiality and Integrity
	3. Protection:
		1. HTTPS(TLS)
		2. Certificate pinning and validation.
		3. VPNs
3. Injection Attacks(e.g. SQL Injection)
	1. Attacker sends malicious input to execute unwanted commands.
	2. Impacts: Data integrity, confidentiality.
	3. Mitigation:
		1. Input validation
		2. Parameterised queries
		3. WAF (Web Application Firewall)
4. Spoofing Attacks
	1. Impersonation of another user/system.
	2. Types: IP spoofing, email spoofing, DNS spoofing
	3. Defense:
		1. Multi-factor authentication.
		2. Token-based auth
		3. IP whitelisting

### Security in the Software Development Lifecycle(SDLC)
- Embed security from the start(shift Left). Bringing security to the starting of the software development lifecycle instead of treating it as a final checklist. Follow coding practices that follows best practices.
- Phases:
	- Requirements: Threat modelling.
	- Design: Secure architecture.
	- Development: Secure coding.
	- Testing: Security Tests, fuzzing.
	- Deployment: Secrets management
	- Maintenance: Patch management

### Best Practices
- Adopt Security by design, IAM security controls should be done at start not at end.
- Use encryption (TLS, at-rest).
- Harden infrastructure, network ports and connection(firewalls, VPCs)
- Validate inputs and sanitise outputs.
- Monitor and log activity.
