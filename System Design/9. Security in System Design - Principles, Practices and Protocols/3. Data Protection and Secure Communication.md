### Why Data protection Matters?
1. Growing threats: Breaches, Man-in-the-middle attacks, data leaks.
2. Regulation(GDPR, HIPAA)
3. User trust and system reliability.

### Encryption
```
Plaintext->Ciphertext->Decryption
Key=secret for coding/decoding
```
Even if data falls into wrong hands it remains unreadable and protected.

### Encryption at Rest and Transit
1. Encryption at Rest:
	1. Protects stored data,
	2. Common Techniques: Full Disk encryption, DB - level encryption.
	3. Used for cloud storage, user files.
2. Encryption in Transit:
	1. Secures data during transmission(HTTP request/response).
	2. TLS/SSL protocols enable secure communication.
	3. Must-have for APIs, user sessions.

### Symmetric vs Asymmetric Encryption:
1. Symmetric: one key (fast, large data).
2. Asymmetric: public/private key pair(secure key exchange). Similar mathematical encryption.
3. Often used together(TLS handshake)

Asymmetric encryption solves the trust and the key exchange problem and the symmetric encryption provides the performance needed for everyday use once the secure channel between two sources is established.

### TLS/SSL and HTTPS
1. HTTPS=HTTP over TLS
2. It ensures confidentiality: Attackers can modify data in transit, integrity: Data is not corrupted and authenticity: It is a legitimate server rather than an attacker impersonating it.
3. TLS handshake: key exchange + cipher negotiation. Once this secure channel is build then same encryption is used for future transaction.

### Hashing and Salting Passwords

1. One-way transformation: When a user creates a password, application computes it's hash and stores that hash instead of the original password. Later during login the entered password is hashed again and compared with the stored value.
2. Use for storing passwords(not reversible).
3. Salting: Add random data to prevent rainbow table(pre-computed user tables)attacks, If two users use the same password then it can create issue and can cause issues for common passwords. 
4. Password specific hashing: bcrpyt or argon2, computationally heavy so brute force is very resource heavy.

### Public Key Infrastructure (PKI)
1. PKI = system for managing digital certificates and keys:
2. Role of Certificate Authorities (CAs): Trusted CA to verify the owners identity.
3. Digital signatures and certificate chains: Chain starts with website certificate, passes through one or more intermediate certificates, and ultimately leads to the trusted root certificate already installed in your browser or your OS. If every link in that chain is valid only then it is considered Secure. 
4. Public key can verify both the sender's identity and that the data has not been modified in recent times.
