Representational State Transfer, It is an architectural style for designing networked applications, It uses standard HTTP methods and stateless communication.
Every request carries the context needed to process it, which means server does not need client-session state between requests.
Why does it matters?
1. Simplicity and scalability: Based on standard HTTP.
2. Interoperability: Works across different platforms. Client in JS, NodeJS or anything can communicate easily as it is based on Web applications.
3. Efficiency: Uses caching, statelessness for performance.
```
REST--->Stateless for easy scaling.(Horizontal scaling is possible)
 |
  ---> Standard HTTP for simple APIs.
 |
  ---> Caching for better performance.
 |
  ---> Uniform Interface for easy integration.
```
### Core principles:
- Client-Server Architecture: Separate UI from Business logic.
- Statelessness: As every request is self contained any server instance can process it. No dependency on any one to hold a session information. Horizontal scaling and fault recovery much simpler.
- Cacheability.
- Layered System: Load balancers, gateways, proxies, security layer and caching layer.
- Uniform Interface.


### RESTful API Design Principles
1. Resource-Based Approach:
	1. GET /users/{id} -- To retrieve a user
	2. POST /orders -- To create new orders
2. Proper HTTP Methods Usage:
   Using proper methods so that functioning is smooth.
	1. GET
	2. POST
	3. PUT
	4. PATCH
	5. DELETE
3. Stateless Interactions:
4. Consistency in URL Structure:
	1. Plural nouns for collections: /users/orders
	2. Avoid including actions in URLs: 
	   ```GET /users/{id}/activate is wrong USE PATCH /users/{id}```
	3. Implement versioning for backward compatibility /v1/users

### Resources and endpoints
Resources: Entities like users, order and products.
Endpoint: Getting information or doing some task.
