HyperText Transfer protocol, Foundation of web communication. It defines rules for requesting and transferring resources. Works over TCP/IP (Port 80 for HTTP and 443 for HTTPS)
Key features:
1. Text-based protocol (easy to read and debug).
2. Stateless (each request is independent).
3. Supports multiple methods (GET, POST, PUT, etc).

### How HTTP Works:
It is like a contract between Server and client.
1. Client Server Model:
	1. Client(Browser or mobile app) makes an HTTP request.
	2. Server(Web server, API) processes the request and sends back a response.
2. Components of an HTTP request:
	1. Method: Defines the action (GET, POST, etc).
	2. URL: The resource being requested.
	3. Headers: Metadata(e.g. user-agent, content type).
	4. Body (optional): Data sent. in POST/PUT requests.
3. Components of HTTP response:
	1. Status Code: It indicated success or failure.
	2. Headers: Metadata about the response.
	3. Body(optional): The actual content returned.

### HTTP Request-Response Cycle:
1. The browser sends request.
2. The web server process the request.
3. The server generates a response and sends it back.
4. The browser renders the response (for a webpage).

### Stateless Nature of HTTP:
HTTP does not retain memory of previous requests and each request is treated as an independent transaction.
It has challenges:
1. Hard to maintain user sessions.
2. Each request must carry all the necessary information we can't ask it question based on the context we have given in the past.

How do we handle state?
1. Cookies: Small pieces of data stored in the browser.
2. Sessions: Server-side storage of user state.
3. Tokens(JWT, OAuth): Used for authentication and authorisation.
Applications build state on top of it through the above things.

HTTP Methods:
Common HTTP methods:
1. GET: Retrieve a resource.
2. POST: Send data to create a new resource.
3. PUT: Update an existing resource.
4. PATCH: Partially update a resource.
5. DELETE: Partially update a resource(Idempotent).


```
HTTP Status Codes:
1xx- Informational (Request received, continuing process).

2xx- Success:
1. 200: OK successful response.
2. 201: Created - Resource successfully created.

3xx- Redirection:
1. 301 Moved permanently - Resource URL changed.
2. 304 Not Modified - Use cached version.

4xx- Client Errors (Mistakes in request):
1. 400 Bad Request
2. 401 Unauthorised
3. 403 Forbidden
4. 404 Not Found
5. 405 Wrong method
6. 429 Too many requests per minute
7. 499 User abortion

5xx- Server Errors 
1. 500 Internal Server Error
2. 503 Service Unavailable
   
   
4xx errors are generally coming from the client side while the 5xx errors are generally coming from our server sides like infrastructure failures, dependency outages or capacity issues.
```
### What about HTTPS?
It is secure version of HTTP, using SSL/TLS encryption.
It ensures data confidentiality, integrity(no tampering) and authentication.
Used for secure websites, online banking and e-commerce.
Works on port 443 instead of port 80.
```
Client --> TLS Encryption --> Server
```
