## TCP (Transmission Control Protocol)
Three step handshake between host and server:
```
Host---SYN--->Server
Host<---SYN/ACK---Server
Host---ACK--->Server
Host<---Established---Server
```
1. Connection-oriented protocol.
2. Reliable, ordered, and error-checked communication: Even if packets of information arrive in a wrong order rather to the destination TCP will re arrange them before giving it to the user. It is essential for workloads where correctness matters more than raw speed. Incomplete or corrupted data is unacceptable. It has an additional overhead so increasing latency.
3. Ensures data reaches the destination correctly.

## UDP (User Datagram Protocol)

Getting data more quickly is more important rather than correctness, no handshake no session setup or ongoing tracking of communication setup.
1. Connectionless protocol.
2. Faster, but no delivery guarantees.
3. No retransmission of lost packets.

### When to use TCP vs UDP
When to use TCP: For data integrity...
1.  Web browsing (HTTP, HTTPS).
2. File transfers (FTP,SFTP).
3. Email (SMTP, IMAP, POP3).
4. Database communication.
5. APIs

When to use UDP: Speed more important than reliability...
1. Video streaming.
2. Online gaming.
3. VoIP calls.
4. DNS lookups (Domain Name System)
