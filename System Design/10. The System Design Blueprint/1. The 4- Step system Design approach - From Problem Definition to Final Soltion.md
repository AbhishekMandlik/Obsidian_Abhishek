### What is System Design?
- Building Scalable, maintainable systems.
- Balancing trade-offs between performance, cost and complexity.
- The importance of clear architecture and thoughtful planning.

### The 4-Step System Design Process
1. Step 1: Understanding the problem and Defining the Scope.
	1. Functional Requirements: Define the core features(e.g. URL shortening, redirection etc).
	2. Non-Functional Requirements: Consider Performance, scalability, reliability and security.
	3. Constraints: Account for time, budget, regulatory and technical limits.
2. Step 2: Estimating Scale and Identifying Bottlenecks.
	1. Estimating Traffic: Analyse Peak load, traffic patterns and user growth.
	2. Identifying Bottlenecks: Pinpoint critical components(DB, CPU, network) that may face performance issues as traffic increases.
	3. Capacity Planning: Estimate Storage, bandwidth and compute requirements to handle growth.
3. Step 3: High - Level Design: Services, APIs and Communication.
	1. Core Services: Break down the system into essential services.
	2. API Design: Define public facing endpoints.
	3. Communication Patterns: Choose synchronous vs asynchronous.
	4. Service interaction: Define how services communicate.
4. Step 4: Making Tech and Infra Decisions Strategically.
	1. Tech Stack Decisions: Choose between SQL/No SQL, data stores and caching solutions.
	2. Scalability and Availability: Implement Load Balancing, autoscaling and replication.
	3. Performance Considerations: Focus on latency, throughput and caching hot data.
	4. Trade-offs: Weigh cost vs performance, simplicity vs complexity in tech choices(Redis for caching vs traditional DBs)
