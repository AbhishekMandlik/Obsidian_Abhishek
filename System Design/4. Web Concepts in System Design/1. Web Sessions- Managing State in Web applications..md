Web applications often need to track user state(Login, Shopping Cart etc). HTTP is stateless meaning each request is independent. Goal is to understand how to maintain state in a web application.
Each request must contain all necessary information.
Techniques for maintaining State:
1. Session-Based Authentication (Server-side session storage + Cookies for session IDs)
	1. Server maintains session state.
	2. The client holds only a session ID.
2. Token-Based Authentication:
	1. The Session state is embedded in token itself.
	2. The Server does not need to track user sessions.
Token based is better for horizontal-scaling.


### Session-Based Authentication
- Server-side session storage.
- Cookies for session IDs.
- User logs in -> Server creates a session and assigns a session ID.
- Session Data is stored server-side, while session ID is sent to the client.
- The client stores the session ID in the cookie. That is passed through every upcoming request until the time is expired and we have to authenticate again.

To organise such data organisation use many techniques like sticky sessions, session replication or a centralised session stores like REDIS.

### Token-Based Authentication
- Encodes session data in a self-contained token.
- No need for server-side session.
- Used in modern stateless authentication.
- Managing expiration, revocation and security becomes more challenging than simply deleting a server-side session.
The token contains all the permissions required: 
1. Token type.
2. Roles.
3. Machine Info/ User Info.
4. Services.
5. appName and other details etc.

Security Concerns in Session Management:
1. Session Hijacking: Stolen session IDs, reducing session lifetimes can prevent this.
2. Cross-Site Request Forgery (CSRF): Unauthorised actions. Malicious site tricks users browser into sending authenticated request to another application where user is already logged in. Because browser automatically includes session cookies the request may appear legitimate. Additional verification and CSRF token can prevent such attacks.
3. Secure Cookie Handling: Avoiding Theft via secure, HttpOnly and SameSite flags.

### Best practice for scaling Session management.
1. Sticky Sessions vs. Distributed Sessions.
2. Storing session data in Redis or Memcached.
3. Stateless authentication(JWTs) for scalability.
