### Redundancy and Redundancy Strategies.
Redundancy is crucial to ensuring system reliability and availability. It prevents a single point of failure. Never allow a single component failure for system to come to halt each one has a backup which can take over silently.
Types of Redundancy:
1. Hardware(servers, storage).
2. Network(Network routes, paths).
3. Services (micro-services, databases).

### N+1, Active-Active, Active-Passive
1. N+1 Redundancy: One Extra instance than that is required.
2. Active-Active: Multiple nodes work together each handling request.
	1. Higher availability and load distribution.
	2. It requires complex architecture.
3. Active-Passive: One active node, others are on stand-by only activated on failure.
	1. Simpler but less efficient for load balancing.
	2. Disaster require in DBs.
	3. Failover has a small lag in between other getting up.

### Graceful Degradation
1. System still operates at a reduced capacity during failures.
2. Helps maintain user experience even when full service is not possible.
3. Critical for ensuring users still benefit from some functionality during outages.
4. Example: In an e-commerce platform if recommendation system is overloaded then what we can do is For some time take the recommendation system down while keeping the Core feature like buying products up. It's good business logic.

### High Availability Patterns in Real-World Systems
1. Load Balancers:
	1.  Distribute traffic evenly across healthy nodes.
	2. Essential for active-active configurations.
2. Replication: Copy data across multiple nodes or data centre's  for availability.
3. Failover: Automatically switch to a backup node/service in case of failure.
All of them are used together in a Distributed and reliable systems.

### Designing for Redundancy
1. Redundant Components: Design with multiple instances of key components to avoid failure.
2. Geographical Redundancy: Use Multiple data centre's or cloud regions for disaster recovery.
3. Automated Failover: Ensure failover happens automatically without manual intervention. Use health checks to monitor failure and without any Human interferance.

### Health Monitoring and Self-Healing Systems
1. Health Monitoring:
	1. Track the status of system components.
	2. Alerts for system failures or performance degradation.
2. Self-Healing Systems:
	1. Automatically repair or replace failed components.
	2. Commonly used in cloud environments for fault tolerance.
We never assume infra is reliable, we create systems that can isolate, interfere and recover with minimal human intervention.
