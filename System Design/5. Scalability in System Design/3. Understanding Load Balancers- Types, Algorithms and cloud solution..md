### Why is load balancing required?
1. High availability: Ensures systems uptime even under high traffic.
2. Traffic distribution: Spreads requests evenly across servers.
3. Prevents Overload: Avoids Overburdening a single server.
4. Improves Performance: Reduces latency and enhances response times.
5. Handles Failures gracefully: Redirects traffic in case of server failure.
6. Supports Scalability: Helps scale systems efficiently as we can increase the number of servers behind load balancers without affecting anything infront of it.
7. This is most useful in sites where the traffic has high and low volumes of traffic during the day to reduce and optimise the costs.

### Types of Load Balancers
Based on Layer: How software is routed?
1. Layer 4(Transport Layer): Operates at TCP/UDP level, distributing requests based on network-level data.
2. Layer 7(Application Layer): Operates at HTTP/HTTPS level making routing decisions based on request content.

Based on Deployment: Where Load Balancer is deployed?
1. Hardware Load Balancers: Specialised devices (eg. F5, Citrix NetScaler)
2. Software Load Balancers: Nginx, HAProxy, Envoy.
3. Cloud Based Load Balancers: AWS Elastic Load Balancers(ELB), Google Cloud Load Balancing.
We have to choose the combination of the above two....

### Load Balancing Strategies
1. Static Load Balancing:
	1. Round-Robin: Distributes requests sequentially to each server.
	2. Least Connections: Directs traffic to the server with the fewest connections.
	3. IP Hashing: Routes requests based on client IP.
2. Dynamic Load Balancing:
	1. Least Response Time: Sends request to the server with the fastest response.
	2. Adaptive Load Balancing: Uses real-time monitoring to make decision. (CPU patterns, health, capacity etc.)
	3. Weighted Load Balancing: Assigns different weights to servers based on capacity.(powerful servers get larger share of requests).

### Load Balancer in Action:
1. Web application with multiple servers.
2. User sends requests and load balancers distributes them efficiently. They decouple clients from individual servers allowing infra to scale, recover from failures without affecting the user experience.

### Choosing the right Load Balancer
1. If your routing decisions depend on URLs, headers, cookies, or application specific rules and not only on TCP/UDP routing Use Layer 7 instead of Layer 4 load balancer.
2. Nginx and HAProxy are good for a stable system. But Managed load balancers automatically handle scaling, health-check and infra management. 
3. Security Concerns: SSL termination and DDoS protections as load balancers are typically the first line of defence.

Choosing right strategy depends traffic patterns and system needs. Essential for highly available and resilient architecture.
