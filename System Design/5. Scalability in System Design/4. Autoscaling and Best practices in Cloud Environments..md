Autoscaling= Automatic adjustment of compute resources based on load.
Ensures performance, availability and cost efficiency. Common in microservices, webapps and event driven systems.

### How Autoscaling works
1. Triggers:
	1. CPU usage.
	2. Memory.
	3. Request Rate.
	4. Queue Length.
2. Types:
	1. Horizontal Scaling: Add/ remove instances.
	2. Vertical Scaling: Resize a single instance.
3. Scaling Policies:
	1. Reactive(based on thresholds).
	2. Predictive(based on trends).
The policies enable infrastructures to adapt automatically to changing workloads, delivering consistent performance while avoiding unnecessary cost.

### Autoscaling Across Cloud Providers
All major cloud providers support built-in autoscaling across compute and container services. 
- AWS - Autoscaling for EC2, lambda, ECS, EKS.
- Azure - Autoscaling via VM Scale Sets, App services, AKS.
- GCP - Autoscaling with MIGs, Cloud Run, GKE, Functions.

### Monitoring and Proactive Scaling
1. Use metrics like:
	1. CPU, Memory, Network.
	2. Queue depth, Custom KPIs.
2. Proactive Scaling:
	1. Predictive algorithms(based on ML or trends).
	2. Scheduled scaling(known traffic patterns).
3. Tools: CloudWatch, Prometheus + Grafana, Azure Monitor, GCP Operations.

### Cost Optimisation Strategies.
- Avoid over-provisioning-scale just enough.
- Use spot/ preemptible instances for batch workloads,
- Apply resource limits and quotas, specially for dev, uat or stg environments.
- Rightsize regularly based on actual usage.
- Use auto-pausing or scale-to-zero features for idle services.
