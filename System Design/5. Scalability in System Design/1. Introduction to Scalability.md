It is ability of a system to handle an increasing amount of work or its potential to accommodate growth. It ensure performance reliability and availability under growing load. If performance degrades, costs explode or reliability suffers the design is not truly scalable. Design for the future not for present. They need to scale because:
1. User base growth.
2. Increasing data volumes.
3. Peak Events.
4. Avoid service degradation downtime.
5. Meet performance SLAs.

### Types of Scalability:
1. Vertical Scaling: Add more CPU/ RAM to one server.
2. Horizontal Scaling: Add more servers to distribute the load.

### Common Challenges in Scaling:
1. Latency: Delay in request and response.
2. Bottlenecks: One slow component = system wide slowdown.
3. Downtime: More node = more failure points. Updates, redeployments, scaling events that can cause outages.
4. Costs: Infra is not free, Autoscaling with limits is important to justify the price.
