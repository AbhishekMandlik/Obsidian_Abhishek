1. Vertical Scaling: Upgrade one machine. Physical cap and has a risk of single point failure, but is easy to implement.
2. Horizontal Scaling: Add more nodes to redistribute traffic/load. Requires additional infra like load balancer, stateless designs and is complex.
3. Diagonal: Start vertical then go horizontal. Common in cloud native apps, Cost-effective + long term ready.

### Examples:
1. Twitter: Moved from monolith -> horizontal scaling.
2. Small startups: Vertical Scaling.
3. AWS lambda apps: Starts diagonal with autoscaling.

When to choose:
1. Startups: vertical(cheaper, simpler).
2. Scaling apps: horizontal(resilience + capacity).
3. Cloud native: diagonal(flexibility + cost balance).
