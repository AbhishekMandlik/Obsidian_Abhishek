### What is performance is system Design?
1. Performance= Efficiency of a system to meet its functional requirements under load.
2. Key Dimensions:
	1. Speed: Time to respond.
	2. Capacity: Amount of work handled.
	3. Efficiency: Resource usage under load.
3. Performance is not a single metric - it's a multi-dimensional goal.
It is to build systems that remain predictably fast, efficient, and reliable as load increases

### Latency vs Throughput:
1. Latency:
	1. Time taken to process one request
	2. Measured in ms or s.
	3. Affects responsiveness.
2. Throughput:
	1. Number of requests processed per second.
	2. Measured in RPS or TPS
	3. Affects scalability.
3. Low Latency != High throughput and vice versa.
4. Both must be balanced based on use case.

### Scalability vs. Responsiveness
1. Scalability: Ability to handle increased load without performance degradation.
	1. Horizontal vs. Vertical Scaling.
2. Responsiveness: Systems ability to respond quickly, Tightly linked to latency.
3. Good design should ensure responsiveness at scale.
4. Load balancers, Caching, DB optimisation, asynchronous processing, distributed architectures all these are used to have fast  response time.

### Measuring Performance
Performance must be measurable and trackable.
1. SLA(Service Level Agreement): External contractual guarantee. Commitment made to the customer. Level of service the business promises to deliver, Often tied to contractual obligations.
2. SLO(Service Level Objective): Internal Target. Business expectation into contractual time for engineers to follow.
3. SLI(Service Level Indicator): Actual metric value. What is happening in production currently to compare with SLO.
Example:
SLA: 99.9% uptime, SLO: 95% request<300ms, SLI: Actual measurement(93% of requests <300ms)
SLA=promise, SLO=goal, SLI=real-time.

### Understanding Percentiles
- Mean/average !+ useful in tail-latency-sensitive systems.
- Percentile provide a better insight:
	- P50: Median
	- P95: 95% requests faster than this.
	- P99: Tail-latency critical for user experience often helps to expose the bottle necks in the system.
- Track tail-latency for real world performance insights. It should not become major source of problems. Check how bad are the slowest request.

### Why Performance Matters in Modern Application
- Users expect instantaneous responses.
- Poor performance leads to:
	- Drop-offs and bounce rates.
	- Loss in revenue.
	- System instability under load.
- Performance is a feature and not a after thought as it impacts user experience, cost and reputation and needs to be monitored continuously.
Performance influences far more than response time.

### Performance Testing Overview
How a system behaves before those situations happen before them happening.
Types of performance testing:
1. Load Testing: Normal Load conditions.
2. Stress Testing: Beyond Normal load conditions.
3. Spike Testing: Sudden large load.
4. Endurance Testing: Over extended time
Goals:
- Identify bottlenecks before they become problem in production.
- Ensure reliability under real-world scenarios.

### Introduction to Performance monitoring
1. Monitoring means it is continuous.
2. Key tools:
	1. APM(New Relic, Datadog).
	2. Logs and Metrics(ELK, Prometheus + Grafana).
3. Track:
	1. Latency and throughput.
	2. Error rates.
	3. Resource usage(CPU, memory, DB queries)
