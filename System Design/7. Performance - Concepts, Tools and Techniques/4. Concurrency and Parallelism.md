What is concurrency?
Concurrency is when multiple tasks start, run and complete in overlapping time periods - not necessarily simultaneously.
Key Points:
- It's about managing multiple tasks efficiently, especially on a single CPU core.
- It is all about task management.
- Can happen on single-core.
- Goal is responsiveness.
A web server handling multiple incoming HTTP requests using asynchronous I/O.

What is parallelism?
It is when multiple tasks are executed simultaneously, typically on multiple CPU cores.
Key Point:
- It is about actual simultaneous execution to speed up performance.
- It is all about task execution.
- Need multi-core for true parallelism.
- Goal is Speed/throughput/
Matrix computation where different parts are calculated in parallel on multiple threads.

### Processes vs. Threads
1. Process:
	1. It has their own memory space. If one process crashes the other ones retain their own functionality. We should separate critical components into different processes. Trade-off is cost.
	2. Heavier to create and switch.
	3. Isolated and safer.
2. Threads:
	1. Multiple threads live in same memory space.
	2. Lightweight and faster.
	3. Can lead to complex bugs.
	4. As they share a memory space, certain conditions like deadlocks, race and data corruption can occur and such bugs are often difficult to reproduce.
	5. Better for performance and efficiency.

### Thread Pools and Worker Models
1. Thread Pools:
	1. Creating new threads and deleting it for a bigger system can Lead to a huge overhead.
	2. So pre-created threads are used for multiple tasks, avoid overhead of creating/ destroying threads. Re-using thread.
2. Worker Models:
	1. Tasks are picked up from a shared queue, and they are distributed to idle workers from a shared queue.
	2. It improves scalability and CPU utilisation. This creates a natural load balancing.
3. Example
	1.  ASP.NET Core uses thread pool to handle request efficiently.
Thread pool optimises resources and Worker models optimise work distribution. Together they are one of the foundation of a scalable high-throughput system.

### Asynchronous Processing
It allows a task to pause while waiting for I/O and freeing thread to do the other useful work. This creates higher throughput, better resource utilisation and the ability to handle many more concurrent request.
- It avoids blocking threads on I/O
- Improve throughput.
Techniques:
- Async await: Async await makes the code look almost like a normal sequential code while remaining  non-blocking under the hood.
- Promises, Future: Work that will be completed later so threads can be unblocked.
- Message Queues (e.g. RabbitMQ, Kafka) for background work. Background workers respond it whenever they are free from the items placed in queue.

### Concurrency in Web Servers:
1. Traditional Servers:
	1. Spawn new thread/pocess per request.
	2. Not scalable for high traffic.
2.  Modern Servers(Node.js, ASP.NET Core, Nginx):
	1. Uses async/non-blocking I/O: When a request is waiting on a file operation, external API call, the server does not keep the thread idle, That thread can be used for different request.
	2. Event-loop or thread-pool models for scalability. It efficiently co-ordinates large number of I/O operation. NGINX- Concurrent connection optimised.

### Common Pitfalls
1. Race Condition:
	1. Multiple threads access and modify shared data concurrently.
	2. Causes unexpected behaviour or corruption.
2. Dead-locks:
	1. Two or more threads wait for each other to release resources.
	2. System get stuck indefinitely.
Strategies to avoid this include Acquiring resources in a consistent order keeping locks for the shortest possible time, using shared mutable state and using timeouts to detect and recover waiting indefinitely. Concurrency introduces complexity, while it improves responsiveness. It creates new failure nodes.

### Best practices and Real-World examples.
- Prefer async/ non-blocking I/O for I/O bound tasks.
- Use thread pools instead of raw threads.
- Always synchronise access to shared data (locks, mutexes etc).
- Detect and avoid deadlocks (lock ordering, timeout strategies).
- Real-world examples:
	- Web Server handling 1000s of Requests: Uses thread pool + async I/O.
	- Background Job Processing: (Worker Model with RabbitMQ).
	- Parallel image Rendering: Each frame rendered on a different core.
