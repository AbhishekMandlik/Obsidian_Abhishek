### Replication Recap:
Replication is the process of copying and maintaining DB objects in multiple DBs.
#### Why Replicate?
1. High Availability: Ensure data availability in case of failure.
2. Load Balancing: Distribute read traffic across multiple servers.
3. Disaster Recovery: Maintain copies of data across different locations.
#### Types of Replication:
1. Master-Slave Replication: One primary DB, multiple replicas for read.
2. Master-Master Replication: Multiple primary DBs, often used for write and redundancy.

### Sharding and Partitioning Strategies Recap:
1. Sharding: 
	1. It splits a large datasets into smaller more manageable pieces.
	2. Goal: Distribute data across multiple servers for better performance.
	3. Example Data across multiple shards based on location.
2. Partitioning:
	1. Dividing data within a single DB into separate tables or partitions.
	2. Range partitioning: Split data by range, like by date.
	3. Hash Partitioning: Split data by a hashing on a key.

### CAP Theorem
Consistency, Availability, Partition Tolerance.
And in highly distributed systems you may need to compromise between consistency or availability for performance. Often system focus on high availability and partition tolerance over consistency for better performance at scale.
### Indexes: Type and Use cases:
- What are indexes?
	- Data structures that improve query performance by reducing the amount of data scanned.
- Types of indexes:
	- B-Tree Indexes: Common for exact match and range queries. Default for most DBs as they work well for exact look-up and range-based queries.
	- Hash Indexes: Best for equality comparisons. Equality searches.
	- Full-Text Indexes: Suitable for low-cardinality columns. Large amount of textual data.
	- Bitmap IndexesL Low cardinality columns. (eg. status flags)
- When to use Indexes:
	- Read-Heavy operations: Indexes speed up query performance.
	- Write-heavy Systems: Be cautious, as indexes can slow-down inserts and updates.

### Normalisation vs De-Normalisation:
1. Normalisation:
	1. Goal: Reduce data redundancy by organising data into tables.
	2. Benefits: Minimises storage costs, eliminates anomalies.
	3. Drawback: Can lead to complex joins and slower read performance.
2. De-Normalisation:
	1. Goal: Introduce redundancy, to reduce join operations and speed up reads.
	2. Benefits: Faster read performance.
	3. DrawbackL Increased storage and potential data anomalies.
3. When to Use each?
	1. N: for transactional systems.
	2. DN: For reporting systems or read-heavy workloads.

### Connection Pooling
It is a technique used to manage DB connections efficiently by reusing established connections instead of creating new ones.
For large applications this is useful, if not it will be using more resources to manage connections than doing the actual work that is required.
1. It reduces overhead caused by frequent connection creation and teardown.
2. Helps handle a large number of concurrent connections effectively.

### Query optimisation
It is the biggest thing that improves performance.
The process of improving the performance of SQL queries.
Reducing the amount of data scanned, reducing unnecessary DB operations and helping the query engine find the most efficient execution path.
Techniques:
1. Proper Indexing.
2. Avoiding N+1 Query problems: Reduce unnecessary DB hots by using joins or batching queries or eager loading Example would be to find how many red balls have number 8 on it. So first query would retrieve all the red balls then each subsequent would be to find among those which has number 8 on it.
3. Using proper joins: Minimising complex joins wherever possible.

### Materialised Views
A pre-commuted query results stored as a table. When a query involves large joins, aggregations or calculation executing it repeatedly can become very expensive. We can calculate it once and store the result for future use. Unlike a regular view which executes its underlying query whenever it is accessed a materialised view stores query result itself.
Benefits:
- Speeds up query performance by avoiding real-time computation.
- Useful in reporting and data warehousing.
Use Cases:
 - Data Aggregation or summary data that does not change frequently.
 - Reporting Systems where fast retrieval is critical.
 - Shift the computation time from query time to refresh time.

### Batching and Pagination
1. Batching: 
	1. Sending multiple operation in a single request or transaction to reduce overhead. It is used for bulk inserts or updates.
	2. Lower network traffic, Fewer DB round-trips and higher throughput.
2. Pagination:
	1. Breaking large sets of data into smaller chunks for efficient retrieval.
	2. Prevents large queries that could lead to timeouts or memory issues.
	3. Ensure responsive UI by fetching data incrementally.
