### Why use Asynchronous Messaging?
1. Loose Coupling: Decouple producers from consumers.
2. Improved Performance: Producers don't block waiting for consumers.
3. Scalability: Consumers can scale independently.
4. Resilience: Message durability adds fault tolerance.
5. Flexibility: Easily add new consumers without changing producers.
```
	Sender-->Queue-->Receiver
```
### Key Concepts of messaging Systems
1. Message: A data packet sent from producer to consumer.
2. Producer: Sends the message.
3. Consumer: Receives and processes the message.
4. Broker/Queue: Stores and delivers messages.
5. Topic/Queue: Logical channel for message delivery.
6. Ack: Acknowledgement of successful processing.

### When to use queues in architecture?
1. When workloads are bursty.
2. When you need decoupling between services.
3. For background jobs.
4. For rate-limited or expensive operations.
5. To buffer spikes in traffic.

### Delivery Guarantees
1. At-least-once(default in many systems):
	1. Message is retried until acknowledges.
	2. May lead to duplicates.
	3. Consumers must be idempotent.
2. At-most-once:
	1. Message sent only once.
	2. No retries -> May result in message loss.
3. Exactly-once
	1. Guaranteed single delivery without duplicates.
	2. Complex and more resource-heavy.
	3. Kafka supports it under specific constraints.
It requires process overhead, and complex system.

### Common Use Cases of message queues
- Order Processing:
	- Decouple frontend from inventory, payments and shipping.
- Logging and monitoring
	- Centralised log processing(e.g. ELK, Kafka).
- Rate Limiting/ Traffic Shaping
	- Queue incoming requests and process at a safe pace.
- Email/ SMS Notification Systems
	- Queue user notifications for async sending.
- ETL Pipelines/ Stream processing
	- Kafka used for real-time data transformation.
It separates work from the rate at which it arrives to rate at which it is processed.
### Best practices for using messaging queues.
1. Use idempotent consumers.
2. Implement dead-letter queues(DLQs).
3. Monitor queue length and processing time.
4. Handle retries and failures gracefully.
5. Choose delivery semantics based on need.
6. Secure your message brokers(auth, encryption).
Design for duplicates, failures, delays and security from Day one.

Kafka excels in high throughput event streaming. RabbitMQ is great for traditional queues. Asynchronous messaging helps build scalable and decoupled systems.
