### Why Caching Matters
- Reduces latency by avoiding expensive recomputation or data retrieval.
- Eases load on backend services and DBs.
- In many large-scale systems it reduces strain on backend systems as those requests that are cache-miss are the only ones handled by backend system. It can increase throughput of the system by several time if done properly.
- Improves user experience and system scalability.
- Critical in low-latency, high-throughput architectures.

### Types of Caching
1. Client-side: Browser memory(e.g. localStorage, service workers).
2. Server-side: Application-level memory or in-memory caches like Redis that sit on top of the Databases.
3. CDN caching: Static content cached close to user(e.g. Cloudflare, Akamai).
4. Database caching: Result-set caching, materialised views. Frequently requested or computationally heavy data to be serves without repeatedly performing costly joins, aggregation or analytic operation.

### Caching Strategies
1. Write-through: Write to cache and Db simultaneously. Consistency writes both DB and cache at same time keeping cache fresh. Latency is a little high.
2. Write-back(write-behind): Write to cache, DB is updated asynchronously. High throughput systems it is common but has durability risk.
3. Lazy loading (Cache-aside): Cache is populated only on demand and only those that are requested,
4. Explicit/manual caching: Developer decides when to cache or evict.

### Cache Eviction Policies
1. LRU(Least Recently Used): Remove least recently accessed item.
2. LFU(Least Frequently Used): Remove least used item by count.
3. FIFO(First in First out:): Remove oldest item added.
4. TTL(Time to live): Automatically expire items after a fixed time duration.
In the last two Freshness matters more than frequency.
### Redis Overview:
Accessing data quickly at scale. Keeps data in memory and hence is very fast.
- In memory key-value store for ultra-fast access.
- Support TTLs(time-to-live), pub/sub, persistence.
- Used for caching, queues, sessions, leaderboards etc.
- Open-source, widely adopted.
It is expensive and for very slow services caching is not important. We can use normal DB like postgres which stores data on hard-drives.
### Real-World Caching
1. CDN: Cache static assets(images, JS, CSS).
2. Product page data: Cache popular catalog queries.
3. User sessions: stored in Redis for fast access.
4. Search results: Frequently repeated queries cached.
5. API response caching: Microservices avoid recomputation.
