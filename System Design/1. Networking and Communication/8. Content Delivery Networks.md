A CDN is a globally distributed network of servers that work together to deliver content efficiently. It exists to:
1. Reduce Latency
2. Enhance content availability
3. Improve load handling
4. Security (Preventing DDoS attack, malicious content restriction and protecting origin servers from direct exposures)

### Why are CDNs needed?
1. High latency due to geographic distance.
2. Overload origin servers.
3. Bandwidth constraints and slow load times.
CDNs move content closer to the user and offloading a significant portionof traffic from origin infrastructure.

### CDN architecture overview:
Components:
1. Origin Servers to store original content.
2. Edge servers - Point of presence (PoPs): Store cached content closer to users across different geographic regions. Reduce latency.
3. Request routing systems: Directs users to the nearest PoP, essentially moving content closer to the user. It not only takes the geographical distance but the network conditions and other aspects as well into consideration.

### How CDN Works and handles a user request?
1. User requests content
2. CDN directs the request to nearest edge server based on geographical location, network latency and server load.
3. Cache Hit: If content is cached, It is delivered instantly.
4. Cache Miss: If content is not cached, The request goes to the origin server, fetched and stored to the edge server for the future use. This dramatically reduces latency, Bandwidth consumption and load on the back-end system.

### How CDNs Improve Performance Reliability and security?
 1. Caching and replication(Reduced Latency):
	 1. Popular content is cached at the edge locations worldwide.
	 2. Cache TTL and invalidation strategies maintain content freshness.
	 3. Reduces origin server load and accelerated content delivery.
2. Load Balancing and Intelligent routing (improved availability):
	1. Traffic is distributed across multiple PoPs.
	2. Geo-based, latency-based, and load aware routing select the best edge location to provide the content.
	3. Automatic failover reroutes traffic during outages.
3. Compression and Content Optimisation(Lower Bandwidth Costs):
	1. Gzip/Brotli compressions reduces payload size.
	2. Image optimisation improves delivery efficiency.
	3. CSS/JS minification reduces download times.
4. Security and Edge protection(Better Security)
	1. DDoS mitigation through rate limiting and traffic filtering.
	2. SSL/TLS termination secures communication.
	3. Protects origin infrastructure from direct exposure.

### Use Cases of CDNs
1. Static vs Dynamic Content Delivery:
	1. Static content: Images, videos etc.
	2. Dynamic Content: API responses, personalised pages
2. API acceleration and Edge Computing (CDNs for APIs):
	1. Reduce api response times. (Cached APIs)
	2. Edge caching for frequent accessed endpoints (Edge Logic).
These are distributed platforms not a singular platforms which is increasing it's use.
