Client, Server and the Network
Client : User-facing application that sends requests.
Server: System that processes requests and returns responses.
Network: The medium that facilitates communication communication between clients and servers.

Basic Steps:
1. Client sends a requests.
2. Request is transmitted over the network.
3. Server and processes the request.
4. Server sends a response.
5. Client receives and processes the response.

Types of Communication:
- Request/ Response Model(HTTP, REST APIs).
- Persistent Connections(WebSockets, FTP sessions, AJAX for background requests).


Request-Response Cycle
1. Browser requests.
2. DNS resolves domain to IP address.
3. Browser sends HTTP GET request to webserver.
4. Webserver processes the request, fetches HTML, queries the DB if needed.
5. Server sends an HTTP response with status code and the webpage content.
6. Browser renders the webpage.
7. If needed then it will parse the image and anything else it requires....

Synchronous vs Asynchronous Communication
1. Synchronous
	1. Client waits for a response to arrive before proceeding.
2. Asynchronous
	1. Client does not wait for the response to arrive and can perform other tasks. For making the function wait before answering the question we should be using await result_of_the previous function().

Stateless and Stateful Server:
1. Stateless Servers:
	1. No memory of the past interaction; each request is independent.
	2. Scalability, easy caching, load balancing
2. Stateful servers:
	1. Maintain sessions information across requests.
	2. Personalisation and seamless user experience.
	3. Used in LangGraph checkpointers and memory.
	4. It requires state, memory management so avoided as and when possible.

Real-World examples:
1. APIs and Microservices.
2. Web Application.
3. Messaging systems.
4. Databases.

Key takeaways:
Client-Server Model is the foundation of every modern applications.
