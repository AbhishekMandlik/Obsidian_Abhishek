In modern system architecture, API's connect clients to the backend services.
Directly exposing backend services can lead to performance security and management challenges. API Gateway is a centralised entry point for all API requests, handling authentication, routing, caching and security. It is front door of a system.....

API Gateways acts as a reverse proxy between clients and backend services. It processes them and forwards them to the correct service.
Key function include:
1. Request transformation.
2. Authentication.
3. Rate limiting.
4. Response handling.
It helps backend team solve business logic rather than infrastructure concerns. It also avoids tight coupling between different teams as they would need to know where and which service to access to find a particular API endpoint.
It should be capable of handling traffic of entire system.

### Benefits of using an API Gateway
1. Security: To protect backend services from direct exposure.
2. Rate Limiting: DDoS attack prevention.
3. Load Balancing: Distribute traffic efficiently.
4. Caching: To increase the speed of response.
5. Request transformation: Converts request format, protocols and headers.
6. Logging and monitoring: Tracks Api performance security events.

Popular API Gateway implementations:
Open Source:
1. Kong
2. NGINX
3. Traefik

Cloud- Based Solutions:
1. AWS API Gateway
2. Google Apigee
3. Azure API management

### When to use API Gateway?
Best for Micro services architectures, multi-client APIs, APIs requiring security, rate limiting and monitoring.
Not for simple monolithic apps and low traffic or internal services.
