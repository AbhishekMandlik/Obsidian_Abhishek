Multiple layer each responsible for specific functions. Independent layers. Separate concernsL UI, business logic and data storage. Better scalability, performance, security and maintainability.

### 2-Tier architecture
Consists of a client Layer and a database layer. The client directly interacts with database without an intermediate business logic layer. 
1. Client Layer: User Interface, application logic.
2. Database layer: Stores and retrieves data.
3. Data flows directly between client and the DB.

Pros:
- Simple.
- Fast for small-scale application.
Cons:
- Poor Scalability
- Security risks as Client layer has direct DB access.
Exposing DB to client layer increases attack surface and makes centralised control more difficult. So only for internal tools.

### 3-Tier architecture
It introduces a middle layer(business logic layer) between UI and the DB.
1. The front end interacts with the business logic layer(API server).
2. The business logic layer processes requests and communicates with the DB.
Pros:
- Improves scalability and security.
- Better Separation of concerns. So changes like scaling in one layer does not affect the other layer and each have their own specific business requirement.
- Easier to maintain.
Cons:
- Higher latency as request has to pass through one additional layer

### N-Tier Architecture
It adds more specialised layers like caching, API gateway and micro-services.
1. It handles high traffic and complex business logic.
2. Allows independent scaling of different services as and when it is required.

It has a very high complexity and tight coupling with quite increase in latency but is secure scalable at each tier and has the best separation of concern. So when the above cons are justifiable this is a good architecture.

### Performance and Scalability Impacts
Latency:
1. More layers = high latency.
2. Solution: Caching, Load Balancing.

Scaling Strategies:
1. Vertical Scaling: Adding resources to a single server.
2. Horizontal Scaling: Adding more server and load distribution.
Horizontal scaling is much more efficient rather than just increasing the capacity of a single server(vertical scaling) deploy more servers.
