Applications are structured as a collection of small, loosely coupled services each responsible for a specific function.
Characteristics:
1. Independently deployable services.
2. Loosely coupled and modular.
3. Scalable and fault-tolerant.

How to identify Microservices?
1. Business Capabilities: Each service should align with a specific Business function.
2. Single Responsibility: A microservice should do one thing well.
3. Data Ownership: Each microservice should have it own DB. It might create coupling problems in the unforeseeable future.
4. Independently Deployable: Should be able to deploy without affecting others.

How to structure Microservices?
1. Decompose by Business Domain: Use Domain Driven Design(DDD) to group services logically.
2. Define Clear APIs: Services should communicate via well-defined REST-APIs.
3. Choose the right Granularity: Avoid making any microservice too large like a monolith to make scalability harder or too small to increase the latency.
4. Implement Observability: Use logging, monitoring and tracing to track service interactions.

### Communication in Microservices
1. Synchronous Communication:
	1. REST APIs(simple but high latency).
	2. gRPC(Efficient in binary format and for better perforance).
2. Asynchronous Communication:
	1. Event-Driven Messaging (Kafka, RabbitMQ, SNS/SQS). Any service can see the event and respond accordingly this creates a loos coupling between each microservice which helps in scaling and independence of each service.

### Challenges of Microservices:
1. Data Consistency: Distributed DB should have same consistency as they are maintained separately by each microservice.
2. Distributed Tracing: It becomes difficult to track as where is the error coming from has to be found out and communication is required in between teams.
3. Network Overhead: More API calls increase latency. Asynchronous communication reduces this by some factor.
4. Security: Authentication, Authorisation and Data protection as surface increased and consistency is required.

### Scaling Strategies in microservices:
1. Horizontal Scaling: Add more instance of a particular service.
2. Auto-scaling.
3. Sharding and DB scaling: Split DB for high-traffic. This is done by read-replicas and sharding. Read-replicas distribute Read-heavy workloads across multiple DB instances, while sharding partition data into smaller segments based on a key such as Customer ID, Geographic regions.

### Real-World Examples of Microservices.
1. Netflix: Uses microservices for video streaming and personalisation.
2. Uber: Scales ride-matching, payments and navigation.
3. Amazon: Each independent service like payments, search and recommendations.
