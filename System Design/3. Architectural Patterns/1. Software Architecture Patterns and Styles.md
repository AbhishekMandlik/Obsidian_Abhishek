Definition: The high-level structure of a software system, defining components, their relationship and the way they interact. It impacts scalability maintainability, performance and system behaviour.
Common Architectural Styles:
1. Monolithic.
2. Layered (N tier).
3. Client-Server.
4. Microservices.
5. Event-Driven.


### Monolithic:
Entire application built and deployed as same unit.
Definition: A single unified where all components are tightly coupled and work as a single unit.
Pros:
1. Simple to develop and deploy.
2. Easier to manage in smaller applications.

Cons:
1. Hard to scale.
2. Difficult to maintain as the codebase grows.
3. High risk of failure: A single bug can take down the entire system.

Used only for small scale applications, startups, simple CRUD-based applications.

### Layered (N-tier) Architecture:
Definition: A system split into multiple layers to separate concerns. 
Responsibilities are clearly defined as layers define function of each unit.
Pros: 
1. Clear separation of concerns.
2. Easier to scale and maintain compared to monolithic.

Cons:
1. Performance overhead due to layers.
2. Results in tight coupling between certain layers.

Use Cases: Enterprise applications, CRM systems, Banking applications.

### Microservices Architecture
Definition: A system built as a collection of small, independent services each focused on a specific business capacity.
Pros:
1. Independent services can be scaled, deployed and developed separately.
2. Flexibility in technology stack for each service.
3. Better fault tolerance.

Cons:
1. Increased complexity in communication and co-ordination.
2. Need for robust DevOps and automation pipelines.

Use Cases: Large-scale applications, e-commerce platform and cloud based-systems.

### Event-Driven Architecture
Definition: A system where components communicate through  events messages instead of direct calls, enabling loose coupling.
Pros:
1. Highly decoupled architecture.
2. Excellent for handling asynchronous workflows.
3. Better scalability for high-traffic systems.

Cons:
1. Debugging and tracing become more complex.
2. Difficult to ensure data consistency across services.

Use Cases: Real-time systems, IoT applications, financial trading platforms.

### Factors Influencing Architecture Selections
1. Business Needs: Business Needs is it event driven or layered?
2. Scalability: Traffic handling by system.
3. Performance: how fast should system respond to users.
4. Maintainability: easy to update, fix and evolve system over time.
