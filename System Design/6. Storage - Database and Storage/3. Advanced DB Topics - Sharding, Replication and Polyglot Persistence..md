### Scaling Strategies - SQL vs NoSQL
1. Vertical scaling(Scale-Up) - Traditional SQL DBs.
	1. Add more SPU, RAM, SSD to a single DB server.
	2. Common with RDBs like MySQL, PostgreSQL, Oracle.
	3. Pros:
		1. Simpler Architecture.
		2. Strong Consistency (ACID guarantees).
	4. Cons:
		1. Limited Hardware capacity.
		2. Cost grows non-linearly.
		3. Risk of single point of failure.
2. Horizontal Scaling(Scale-Out) - Modern NoSQL DBs.
	1. Add more DB nodes to distribute data and load.
	2. Common with NoSQL DBs like MongoDB, Cassandra, DynamoDB.
	3. NoSQL have a relaxed consistency to achieve higher availability and scalability.
	4. Pros:
		1. Elastic scalability.
		2. Handles large-scale traffic and big data.
		3. Better fault tolerance.
	5. Cons:
		1. Complex architecture,
		2. Weaker Consistency (often eventual)


### What is replication?
Definition: Copying data from one DB node to another for redundancy and performance.
Benefits:
1. Fault tolerance.
2. Read performance improvement.
3. Data availability.
Trade-offs in real world systems(CAP Theorem):
- Replication may favour availability.
- Strong consistency may sacrifice availability.
- The moment data exists on multiple nodes keeping every copy perfectly synchronised becomes challenging. Eventual consistency is preferred.

### Leader-Follower Replication:
Write permission is done by leader only while followers can read only. It seperated read responsibilities from Write responsibilities.
How it works:
- Writes go to the leader.
- Reads from Followers.
Consistency Consideration:
- Asynchronous replication = possible lag.

### Read Replicas
Mainly for read -heavy applications. It creates additional copies of data that are read only. Primary DB is Read/Write while the rest and others are Read Only replicas. During traffic spikes replicas can be added consistently and are updated asynchronously so there is a little lag in between them.
Use case:
- Scaling read-heavy workloads
Differences from Leader-Follower:
- Often used just for load balancing reads.
- Doesn't take part in writes.

### What is Sharding?
Each shard portion of the data and process only that part of data. 
Splitting data across multiple DBs(shards) to scale horizontally.
It is needed to improve Performance and storage limits of single node.
It is later scaling strategies, at early stage replication is enough and easier to implement.
Types of Sharding:
1. Horizontal Sharding: Rows are distributed across shards(most common).
2. Vertical Sharding: Tables or columns are split across shards based on function or access pattern.

### Sharding Strategies:
1. Range Based Sharding: Data is partitioned by range values. If  new data continuously fall into the same range one shard can become overloaded, while others can remain lightly used.
	1. Split by value ranges (e.g. user_id 1-1000).
	2. Can create hotspots.
2. Hash-Based Sharding: It addresses imbalance by Range-Based sharding. It creates hash mapping to distribute effectively over all other shards. Adding or removing shard can cause a large data to be redistributed.
	1. Distribute using a hash function.
	2. Even distribution but harder to query ranges.
3. Consistent Hashing for Resilient Hash-Based Sharding. Solve The problem in Hash-Based Sharding. It minimises the data movement during topology changes, it allows systems to scale more gracefully.
	1. Traditional hashing breaks when nodes are added/removed(re-hashing everything).
	2. Consistent Hashing solves this: Only a subset of keys need to be re-mapped when topology changes.
	3. Enables better elasticity and fault tolerance.
4. Geo-Based Sharding: It optimises for latency and locality instead of optimising distribution only.
	1. Shard by user region/location.
	2. Useful in geo-distributed systems

### Polyglot Persistence
Using different types of DBs for different components/services.
Each DB excels at different things(search, analytics, relations).
It boosts performance in complex systems.
Benefits:
1. Better performance.
2. Optimised storage and queries.
Start with one DB then introduce new DB when business demands it.
