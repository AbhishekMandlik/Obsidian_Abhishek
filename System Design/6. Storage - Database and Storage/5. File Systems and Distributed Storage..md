It defines how data is stored and retrieve on disk. Examples: ext4, NTFS, XFS.
Handles file metadata, directories and permissions.

### Key Characteristics of Traditional File Systems
1. Hierarchical structure(folders/files).
2. Limited Scalability across machine.
3. Suited for single-node systems.
4. Uses: Personal devices, small servers.

### Distributed File System
1. Allows file to access across multiple nodes
2. Ensures Redundancy, fault tolerance.
3. It appears as a single file system to the user.
4. Key- Benefit: Scalability and reliability. It can be scaled across as many devices as you want and as it is replicated across multiple machine the system can continue operating even when individual server fails. Example HDFS: Hadoop Distributed File System - Big Data Analytics.
5. Use Cases:
	1. Big data analytics (Hadoop, Spark).
	2. Enterprise Storage (shared file systems).
	3. Scientific computing.
	4. Media and backup systems.
This allows systems to scale and remain resilient as data and demand continue to grow.

### DFS Architecture and How Replication Works
1. Name Node: Manages metadata, file hierarchy.
2. DataNodes: Store actual data blocks
3. Each block is stored on multiple data nodes according to configured replication factor. This increases fault tolerance. 
4. Data blocks are replicated across nodes:
	1. Ensures availability during node failures.
	2. Replication factor configuration.
	3. HDFS default = 3 copies.
5. Block size and striping concepts.
Horizontal scalability, High Availability Resilience against hardware failures qualities that are very essential when managing data across hundreds or thousands of servers.

### Scalability and Fault tolerance:
- DFS can scale horizontally by adding nodes.
- Automatic rebalancing of data.
- Supports high-throughput workloads.
- Built- in failure recovery mechanism. This is done by continuous monitoring of the data and hence failure is handled through them.
