It refers to datasets too large or complex for traditional data-processing tools.
Emerged due to growth in data generation, and it requires storage, processing and analysis strategies like DFS and parallel processing to handle.

### 6 V's of Big Data:
1. Volume:
	1. Refers to the massive amount of data generated and stored.
	2. Example: Social Media, IoT devices, transaction logs.
2. Velocity:
	1. Speed at which data is generated, collected and processed.
	2. Real-time data from stock markets, clickstreams or sensor feeds.
3. Variety:
	1. Diversity of data formats and types.
	2. Includes structured, semi-structured(JSON, XML) and unstructured.
4. Veracity:
	1. Trustworthiness, accuracy and quality of data.
	2. Challenges include noise, inconsistencies, missing values and ambiguity.
	3. Cleaning data.
5. Value:
	1. The usefulness of data - i.e. the insights, decisions or business impact derived from it, without it data is just a storage overhead.
6. Variability:
	1. The inconsistency or unpredictability in data meaning, format or flow.
	2. Changing user behaviour, evolving language or fluctuating sensor readings.

### Why traditional storage fails at scale?
1. Limited Scalability - not built for big data.
2. Traditional architecture were not designed for large demands. As demand increases throughput becomes a constraint and they can become performance bottlenecks - not optimised for parallel reads/writes.
3. Cost inefficiencies: Expensive to scale up (vertical scaling).
4. Lack of fault tolerance - no data replication or distributed recovery hence servers when fail it becomes an emergency.

### Common Big Data Workloads
- Logs and Events: Application logs, system logs, server metrics.
- Clickstreams: User navigation paths on websites and apps.
- IoT Data: Sensor streams, smart devices.
- ML pipelines: Feature extraction, model training, data versioning.
All these have a main thing in common. They require large amounts of data, they produce continuous large data which requires storage, DFS and replication for consistency and reliability.

### Batch vs Stream Processing:
Storing Big Data is only the first step, the real value comes from processing it efficiently.
How quickly you need to process the data.
1. Batch Processing:
	1. Process large data chunks at once.
	2. High throughput, higher latency.
	3. Hadoop or Spark(match mode).
	4. Use for Historical analysis, ETL jobs, nightly aggregations.
2. Stream Processing:
	1. Processes data in real-time as it arrives.
	2. Low Latency, continuous. processing.
	3. Apache Kafka, Spark streaming, Flink.
	4. Real-time monitoring, fraud detection, recommendation systems.
Batch prediction answers the question as to what happened while stream processing answers the question what is happening in real-time?
