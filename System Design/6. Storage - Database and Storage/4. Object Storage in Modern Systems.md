### What is object Storage?
A storage architecture that manages data as objects, not files or blocks.
Each object contains:
1. The Data itself.
2. A unique identifier(key).
3. Metadata.
Unlike traditional storage, it is scalable, distributed and suited for unstructured data.

### Key Concepts in Object Storage
1. Object: Self-contained unit of data.
2. Bucket: Logical container for storing objects(like folder).
3. Metadata: Custom data that describes the object(e.g. MIME type, timestamps, custom tags)
### Popular Object Storage Platforms
1. Amazon S3: Industry Standard, rich ecosystem, high durability(11 Nines Durability).
2. Google Cloud Storage (GCS): Simplified tiers, ML-friendly.
3. Azure Blob Storage: Strong integration with Microsoft stack.
4. On-prem alternatives (MinIO, Ceph) for hybrid/cloud-native use.
### Common Use Cases:
1. Media Storage(videos, images, large files).
2. Backups and archives.
3. Data lakes for analytics.
4. Static Website hosting (eg. via S3).
5. IoT and ML data pipelines.
### Important Consideration with Object Storage
1. Performance Considerations:
	1.  Latency: Object Storage has higher latency than block/file.
	2. Throughput: Designed for massive parallel access.
	3. Consistency: Eventual consistency in some platforms(s3).
	4. Access patterns: Suited for write-once, read-many workloads.
2. Cost Considerations:
	1. Storage class tiers: Standard, Infrequent Access, Archive (S3 Glacier).
	2. Charges: Storage, requests(PUT, GET), egress bandwidth.
	3. Best Practices:
		1. Use Lifecycle rules for archiving/deletion.
		2. Monitor usage and optimise classes.
Charger can exceed budget if workloads are not carefully designed. So automatic lifecycle rules is important, moving the older data to archived places.
